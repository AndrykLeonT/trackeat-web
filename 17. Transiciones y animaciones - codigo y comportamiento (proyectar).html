Transiciones y animaciones — código y comportamiento

la transición dónde va timing-function delay property y all @keyframes fill-mode direction iteration y play-state altura auto movimiento reducido

transition disparador y dos estados

Una transición necesita algo que la dispare. Sin disparador no pasa nada.

.bola {
  transform: translateX(0);
  transition: transform .6s ease;
}

/* El disparador: una clase, :hover,
   :focus, o un cambio desde script */
.bola.movida {
  transform: translateX(420px);
}
A

Qué pasa El navegador interpola entre los dos valores. Tú declaras el principio y el final; los cuadros intermedios los pone él.

Dónde se declara la transición el error más común del tema

En la regla base va y regresa. En :hover solo va.

/* BIEN — la transición vive en la base */
.a { transition: transform .5s ease; }
.a:hover { transform: translateX(300px); }

/* MAL — solo mientras el puntero está
   encima existe la transición */
.b:hover {
  transform: translateX(300px);
  transition: transform .5s ease;
}
bien
A
mal
B

Qué pasa Las dos van igual de suave. Al regresar, la de abajo salta de golpe: cuando se quita el disparador ya no existe la regla que declaraba la transición.

transition-timing-function cómo se reparte el tiempo

Las cinco salen al mismo tiempo y llegan al mismo tiempo. No se ven igual.

.a { transition-timing-function: linear; }
.b { transition-timing-function: ease; }
.c { transition-timing-function: ease-in; }
.d { transition-timing-function: ease-out; }
.e { transition-timing-function:

Qué pasa linear se ve mecánica. ease-out es la que mejor se siente para algo que entra. La quinta se pasa del destino y regresa: eso es un rebote, y sale de cuatro números.

transition-duration y -delay cuánto tarda y cuándo empieza

El retraso escalonado es lo que hace que un menú se sienta hecho a mano.

.item:nth-child(2) { transition-delay: .1s; }

transition-property qué se transiciona, y por qué no «all»

Con all el navegador vigila todo, incluso lo que no querías mover.

/* Explícito: solo estas dos */
.a {
  transition-property: transform, opacity;
  transition-duration: .5s;
}

/* Atajo con todo junto */
.a { transition: transform .5s ease, opacity .3s linear; }

/* Cómodo, pero mueve cosas que no
   pediste y cuesta más */
.b { transition: all .5s ease; }

todo lo que cambie

Qué pasa Las dos cambian de color, de tamaño y de posición. La izquierda solo transiciona el movimiento y el color salta de golpe; la derecha transiciona todo. Ninguna está mal: lo que está mal es no saber cuál escogiste.

@keyframes una secuencia con pasos intermedios

No necesita disparador. Arranca sola y puede tener los pasos que quieras.

@keyframes latido {
  0%   { transform: scale(1); }
  30%  { transform: scale(1.25); }
  60%  { transform: scale(.95); }
  100% { transform: scale(1); }
}

.caja {
  animation: latido 1.2s ease-in-out;
}

/* La práctica pide tres pasos o más */
latido

Qué pasa Nadie la tocó. Una transición necesita que algo cambie; una animación se ejecuta por su cuenta y pasa por estados intermedios que la transición no puede expresar.

animation-fill-mode qué pasa antes y después

Sin esto, al terminar la animación el elemento regresa de golpe a como estaba.

@keyframes correr {
  from { transform: translateX(0); }
  to   { transform: translateX(400px); }
}

.a { animation: correr 1.4s none 1s; }
.b { animation: correr 1.4s forwards 1s; }
.c { animation: correr 1.4s backwards 1s; }
.d { animation: correr 1.4s both 1s; }

/* Todas con 1 segundo de retraso,
   para que se vea qué hacen antes */

1

Qué pasa Miren el primer segundo, antes de que arranquen: las de backwards y both ya están en la pose inicial. Y miren el final: las de none y backwards regresan de un salto.

animation-direction de ida, de regreso, o de ida y vuelta

Con alternate no hace falta escribir el regreso en los keyframes.

.a { animation-direction: normal; }
.b { animation-direction: reverse; }
.c { animation-direction: alternate; }

/* Las tres con iteration-count: 2 */

Qué pasa reverse recorre los keyframes al revés. alternate va y viene: la segunda repetición se reproduce de regreso.

iteration-count y play-state cuántas veces, y pausar

Una animación se puede pausar sin quitarla, y sigue desde donde iba.

.giro {
  animation: girar 2s linear infinite;
}

.giro.pausada {
  animation-play-state: paused;
}

/* infinite es literal: no se detiene
   sola nunca. Úsalo con cuidado. */
∞

Qué pasa Al pausar no regresa al inicio: se queda donde iba. Al soltar, sigue desde ahí.

El panel que se despliega por qué height: auto no transiciona

No se puede interpolar hacia un valor que el navegador aún no conoce.

/* NO funciona: auto no es un número */
.panel { height: 0; transition: height .5s; }
.panel.abierto { height: auto; }

/* SÍ funciona, y es la forma moderna */
.panel {
  display: grid;
  grid-template-rows: 0fr;
  transition: grid-template-rows .5s ease;
  overflow: hidden;
}
.panel.abierto { grid-template-rows: 1fr; }
.panel > div { min-height: 0; }

prefers-reduced-motion la condición que sí se revisa

Hay quien se marea con esto. No es un detalle: es parte de la entrega.

/* Lo mínimo que se acepta */
@media (prefers-reduced-motion: reduce) {
  .tarjeta, .panel, .bola {
    transition: none;
    animation: none;
  }
}

/* Mejor todavía: no quitar el efecto,
   cambiarlo por uno que no desplaza */
@media (prefers-reduced-motion: reduce) {
  .tarjeta {
    transition: opacity .2s;
    transform: none;
  }
}
